# Nova: живой интернет-прогон G14 → G20

20 сентября 2026 года выполнен реальный запуск на данных PyPI и GitHub.
Итог **PARTIAL: 6 из 7 типов задач освоены**, шесть новых программ приняты
в поколения G15–G20. Длительность полного запуска — 285,36 секунды.
Исходники `nova_core` и активная грамматика во время опыта не менялись.

| Задача | Поколение | Holdout | Новые источники после обучения |
|---|---:|---:|---:|
| Сумма размеров файлов дистрибутивов | G15 | 3/3 | 3/3 |
| Количество, сумма и сортировка размеров | G16 | 3/3 | 3/3 |
| Сериализация полученной сводки в JSON | G17 | 3/3 | 3/3 |
| Сумма звёзд и форков репозитория | G18 | 3/3 | 3/3 |
| Запись с суммой и разностью счётчиков | G19 | 3/3 | 3/3 |
| JSON с именем и унаследованным SHA-256 | G20 | 3/3 | 3/3 |
| Числовая сортировка версий пакетов | WITHHOLD | 0/3 | Нет принятой программы |

При выполнении сделано **18 HTTPS-запросов**, каждый получил HTTP 200.
Использованы девять пакетов и девять репозиториев. Первые 12 ответов дали
обучающие и holdout-примеры. Последние шесть запросов выполнены после фиксации
генома G20. Принятые программы дали **18/18** правильных новых ответов.
В общей сводке стоит **18/21**: три запроса к неосвоенной задаче отмечены
как неуспех, поскольку активной программы у неё нет.

Дополнительно прошли 20/20 случайных проверок SHA-256, включая Unicode,
нулевой символ, границы блоков и 1024 байта. Это отдельная синтетическая
проверка границ; она не включена в число интернет-задач. Полная регрессия
активных навыков — **114/114 по 19 навыкам**, включая все 13 унаследованных.
Холодный запуск отдельного процесса и полный семантический replay — PASS.
Сохранены все 34 исходных события G14; итоговый журнал содержит 42 события.

## Что построила сама Nova

Оператор написал адаптер HTTPS, постановки задач, проекции входных данных и
эталонные проверки. Ядро само выбирало задачи из зарегистрированной очереди,
перебирало программы и принимало их через собственный admission.
Готовые реализации решений и предложения LLM в синтез не подавались.

G16 использует программу G15, G17 — программу G16. Удаление используемого
родителя в каждом случае снижает holdout с 3/3 до 0/3. Также G19 использует
G18, а G20 — прежний SHA-record из G14; их проверки удаления родителя тоже
дают 0/3. Это наследуемая композиция в действующем языке, а не создание
нового примитива или произвольное переписывание runtime.

Интернет-канал реализован в `scripts/run_internet_tasks.py`: он получает
реальные ответы двух публичных API и передаёт их ограниченные проекции
ядру. В этом запуске Nova не выбирала сайты и не формулировала постановки
задач самостоятельно. Загруженные Python-пакеты и код репозиториев не
исполнялись: использовались их метаданные.

## Почему седьмая задача не прошла

Зафиксированные обучающие списки версий уже находились в правильном
числовом порядке. Поэтому простое копирование входа совпало с 3/3
обучающими ответами. На отдельных holdout-пакетах строковый порядок
отличался от числового: копирование дало **0/3**, admission его отклонил
с причиной `HOLDOUT_FAILED`.

Это ограничение данного обучения и обобщения, а не доказательство
невозможности алгоритма в принципе. Набор после неудачи не переделывался,
проверочные ответы не использовались для повторного подбора решения.
После отказа ядро вернуло `IDLE / NO_ELIGIBLE_DEFICIT`; задача получила
`EVALUATION_CONSUMED`. Самостоятельный сбор различающих примеров и
продолжение этой неудачной линии данным прогоном не продемонстрированы.

## Воспроизведение

Рабочее состояние и его резервная копия созданы локально. В Git сохранён
полный журнал, позволяющий восстановить G20 без обращения к интернету.
Для этой контрольной точки нужен Python 3.12:

```bash
python scripts/run_development_chain.py \
  --restore experience/internet-tasks-v1/journal.json \
  --state state/restored-internet-g20.sqlite
python -m nova_core --state state/restored-internet-g20.sqlite status
```

Отдельный новый интернет-опыт с прежней исходной точкой G14:

```bash
python scripts/run_internet_tasks.py \
  --output experience/internet-tasks-repeat \
  --state state/internet-tasks-repeat.sqlite
```

Нужны новые пути; старые результаты не перезаписываются. Ответы API со
временем меняются, поэтому новый запуск не обязан совпасть с этим опытом.
Исторический replay работает по сохранённым входам и не зависит от API.
Прогон завершён, фонового процесса после него нет.
