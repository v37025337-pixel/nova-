# G20 → G21 → G22: использование Python-инструментов

Nova 0.6.0 получила две проверенные способности: сравнение числовых компонентов
строк и сортировку через унаследованное сравнение. Исходная неудача
`290-numeric-version-order` сохранена в истории. Новая программа решает все три
её прежних неудачных примера и новые независимые от поиска перестановки.

| Поколение | Что построило ядро | Новые проверки | Полная регрессия после restart |
|---|---|---:|---:|
| G21 | Сочетание `str.split`, `float`, отображения по списку и `operator.lt` | 24/24 | 162/162, 20 навыков |
| G22 | Сортировка с явным вызовом программы G21 | 24/24 | 192/192, 21 навык |

Удаление нового примитива G21 даёт 0/24. Для G22 отдельно удалены его новый
примитив, программа G21 и примитив G21: каждый раз получено 0/24. Обе генерации
восстановлены в отдельных процессах полным семантическим replay. На отдельных
копиях выполнены точные откаты G21 → G20 и G22 → G21 с регрессией прежних навыков.

## Что сделало ядро, что добавил разработчик

Разработчик добавил каталог 14 чистых Python-функций, ограниченный язык их
сочетаний и правило переноса проверенного сравнения на задачу перестановки.
Runtime и конструктор целей остаются написанными разработчиком. Произвольные
импорты пакетов и доступ к файлам/сети из исполняемого кандидата не добавлены.

Nova повторно обнаружила сохранённый дефицит после изменения runtime, запросила
каталог, выбрала функции по обучающим данным и за 1530 вариантов составила
сравнение. После restart она сама сформировала цель переноса и породила программу,
которая обращается к унаследованной программе G21. Новых операторских задач в
журнал не добавляли. Библиотечная сортировка — готовый алгоритм Python; её
самостоятельное изобретение не заявляется.

Установленные научные пакеты перечислены в квитанциях среды. Исполняемый мост
использует стандартную библиотеку; запись пакета в инвентаризации не означает
предоставление ему произвольного доступа из кандидата.

## Проверка и границы вывода

[Протокол](protocol.json) и код опубликованы в
[81d1201](https://github.com/v37025337-pixel/nova-/commit/81d120152f7b18217d5d21db0a43c45f4941745c)
до создания новых оценочных примеров. Затем в журнале отдельно зафиксированы
каждая цель, каталог инструментов и кандидат. Только после этого внешний
процесс создавал 24 примера со случайностью ОС. Он получает контракт и frozen ID,
не получает исходник кандидата. Порог 100% не менялся, повторной подгонки после
fresh-ответов не было. Исходные 54 события G20, включая прежний `WITHHOLD`, сохранены.

Перед freeze разработчик проверял новый генератор на открытых обучающих данных
G20. Новых fresh-ответов тогда не существовало. Внешний оценщик написан тем же
разработчиком и запущен отдельным процессом; это не аудит независимой организацией.

Область fresh-проверки: неотрицательные десятичные компоненты 0…999999,
2–5 компонентов, перестановки по 8 строк. Проверены равенство, ведущие нули,
короткие/длинные префиксы, различие числового и строкового порядка и стабильность
дубликатов. Это порядок целочисленных кортежей, не весь стандарт PEP 440.
Генератор выбрал преобразование через `float`; точность за пределами указанной
области не доказана. Это ограничение сохранено в отчёте.

Цели по-прежнему происходят из операторской задачи, а механизм их обнаружения
ограничен двумя законами сравнения и одним правилом переноса. Поэтому результаты
подтверждают **развитие навыков с помощью библиотек**. Строгий рубеж трёх полностью
самостоятельных поколений не объявляется пройденным.

После G22 отдельный процесс вновь запустил выбор цели. Ядро вернуло
`IDLE / NO_SUPPORTED_ENDOGENOUS_DEFICIT`. Третью задачу оператор не подставлял:
фактический результат — два новых поколения, а не три.

## Восстановить и использовать результат

Для сохранённого журнала нужен Python 3.12 и Linux с поддержкой seccomp.
Назначение восстановления должно быть новым файлом:

```bash
python scripts/run_development_chain.py --restore experience/python-learning-v1/journal.json --state state/replayed-g22.sqlite
python -m nova_core --state state/replayed-g22.sqlite predict auto-1ec0944f5900db6acb62dcb6 --input '{"left":"1.9","right":"1.10"}'
python -m nova_core --state state/replayed-g22.sqlite predict auto-859fa997bbbd259650f164c3 --input '{"versions":["1.10","1.2","1.9"]}'
```

Ожидаемые результаты: `true` и `["1.2", "1.9", "1.10"]`.
Исходную задачу со старой неудачей не переименовывают и не переоценивают;
новые навыки имеют собственные нативные ID.
