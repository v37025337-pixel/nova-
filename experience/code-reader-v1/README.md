# Присланный UniversalCodeReader подключён к Nova

Проверена рабочая копия присланного файла с исправлениями, описанными в
`docs/code-reader.md`. На 24 реальных исходниках (21 модуль ядра и 3 файла
инструмента) reader построил 39 407 узлов Python AST. Исходные байты всех файлов
восстанавливаются точно; повторных идентификаторов, незамкнутых ссылок и ошибок
разбора нет. Читаемые исходники не исполнялись.

Общий локальный набор: 108/108 тестов на Python 3.12.14. Проверены также
испорченный BOM, UTF-16 BE, произвольные бинарные байты, JSON-пути и повторные
ключи, суррогаты, маркировка уровня разбора, запись производного синтаксиса
в настоящий `Kernel.observe()` с последующим закрытием и восстановлением
состояния, CLI и отсутствие исполнения читаемого файла.

`source-read-report.json` содержит результаты и хеш каждого из 24 файлов;
`tests.txt` — полный локальный запуск тестов. `canonical/code-reader.json`
фиксирует хеш присланного оригинала и три рабочих исходника инструмента.
Модули `nova_core` и источник replay G22 не изменялись этой интеграцией.
Сохранение структуры кода не считается пониманием любой программы,
самостоятельным изобретением алгоритма или новым поколением ядра.

21 сентября пользователь явно разрешил публикацию подготовленных изменений
в публичном `v37025337-pixel/nova-` и добавление присланного reader. Это новое
разрешение устраняет причину предыдущего отказа автоматической проверки.
Прежний отказ сохранён в отчёте observation-goals-v1 как историческое событие.
