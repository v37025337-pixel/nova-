# Nova 0.7: наблюдения связаны с выбором цели, новой способности нет

**Итог: PASS для соединения наблюдений с выбором цели; WITHHOLD для полезного
автономного улучшения. Активная генерация — G22.**

До изменения `Kernel.step()` на проверенной G22 возвращал
`IDLE / NO_SUPPORTED_ENDOGENOUS_DEFICIT` даже после сохранения внешних данных.
Разработчик добавил отдельный вход полных структурированных наблюдений,
ограниченный парсер JSON/CSV, семейство начальных предсказателей и конструктор
целей по повторяющимся ошибкам. Конкретную цель и программу выбирает ядро.
Эта инженерная работа не называется самостоятельным изобретением механизма Nova.

URL, что использовались в предыдущем отрицательном эксперименте. Транспорт
передаёт полный декодированный ответ; он не выбирает поля, задачи или ответы.

Цель выбрана нативно и содержит проверяемый контракт, пороги и ссылки на ошибки.
Но это ещё слабый выбор: идентификатор набора данных не обязан определять
таксономический код. Исходная точность 1/8 не устанавливает обучаемую зависимость.
Текущий приоритет «больше ошибок» может предпочесть бессодержательное или
непредсказуемое соответствие. Это измеренный предел нового механизма, а не
доказательство понимания биологии либо системного интеллектуального дефицита.
Следующая инженерная задача — проверять обучаемость и ожидаемую пользу цели
до расходования полного бюджета синтеза.

Кандидат отсутствует. Свежая независимая оценка новой способности, её ablation,
admission и откат нового поколения на реальных данных не выполнялись.
Проходящие regression/replay не превращают этот отрицательный результат в
рост интеллекта. Положительный путь admission/restart/rollback проверен отдельно
на синтетических контрольных данных в `tests/test_observation_goals.py`.

## Что изменено

- `nova_core/observations.py`: разбор полных документов, воспроизводимые ссылки
  на записи, проверка хешей, устранение повторов, исходные предсказания,
  измерение ошибок, выбор и фиксация цели, синтез только по обучающим строкам.
- `Kernel.observe()` и команда `observe`: наблюдения проходят через тот же
  журнал и тот же цикл `Kernel.step()`. Документы алгоритмических спецификаций
  в `study()` сохранены как отдельный вид данных.
- Наблюдённые входы нельзя повторно выдать за свежий holdout; это сохраняется
  после вытеснения документа из рабочего окна и перезапуска. Перехешированная
  подделка свидетельств отклоняется семантическим replay.
- Runtime v7 и точная совместимость с v6: старые хеши не ослаблены. Обновление
  требует полного воспроизведения истории и регрессии наследуемых программ.
- В CI добавлено восстановление результата этого опыта. Удалённый CI для этой
  ветки пока не запускался: публикация кода заблокирована автоматической проверкой.

Ограничения parser/selector заданы разработчиком: 262 144 байта на документ,
до 16 скалярных полей и 128 записей на документ, рабочее окно 32 документа,
до 64 пар за выбор. Усечение явно отражено в `limited`. Полные принятые тексты
остаются в журнале; хеши повторов и исключения известных входов не удаляются
при сокращении рабочего окна. Пара полей рассматривается внутри одного хоста
и пути структуры, значения с противоречащими ответами исключаются.

## История и заморозка

Основа: `main` `7218a570f66ef9a5fe694d556814bd1311dff43e`.
Код и протокол зафиксированы локальным commit
`202bd6d1420346d1970e0c5f7af74fbc7d4e28b9` до новых сетевых запросов.
После явного разрешения пользователя тот же набор файлов опубликован в commit
`9bed5b6bf57e7662caf8543c73004f2a1302bf15`. Полное соответствие локальных и
опубликованных commit с проверенными Git tree находится в
[`publication.json`](publication.json). Это последующая публикация локальной фиксации.
Отправку в публичный GitHub отклонила автоматическая проверка из-за отсутствия
явного разрешения на публикацию нового кода. Поэтому публичная предварительная
регистрация и независимый внешний аудит не заявляются. Предыдущие архивы
использовались как открытые данные разработки; повторное получение не означает,
что все записи неизвестны ядру или разработчику.

Исходные 72 события сохранены без изменения. Добавлены один `runtime_upgrade`,
14 `observation` и три `autonomy_step`. Genome остаётся
`81721cc4fe5cd51b96114598b3c19b72f52f18f075065f7e0ee371381e81947d`.
Новый head журнала:
`9df783c1ee135072df71846ee2d35ea3e23151ca26998c6e67015d5ad024a89b`.

## Проверка и продолжение

```bash
python -m unittest discover -s tests -v
python scripts/verify_release.py
python scripts/run_development_chain.py --restore experience/observation-goals-v1/journal.json --state /tmp/nova-observation-restored.sqlite
```

Путь восстановления должен быть новым. Оно не делает сетевых запросов и
проверяет решение ядра и неудачный поиск, а не только последовательность хешей.
`actions.json` содержит точную цель и ошибки, `receipts.json` — ответы источников,
`ingestion.json` — фактические приёмы и отказы, `regression.json` — все результаты
прежних навыков, `journal.json` — полное состояние для продолжения.
`verification.json` содержит компактный итог проверок.
