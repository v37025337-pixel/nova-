# Проверка механизмов расширения языка в 0.3

Это два разных испытания. Контроль над словной алгеброй проверяет работающие
механизмы. Продолжение G12 проверяет именно SHA-256 по строгому критерию G13.
Успех первого не засчитывается за успех второго.

## Пять изменений

| Прежний дефицит | Реализация и проверяемое поведение |
|---|---|
| Нет диагноза | `capability.diagnosis`: история причин, бюджет/ограниченный фронт поиска, отсутствие знаний, гипотеза о нехватке операций; без заявления о доказанной невозможности |
| Нет собственной цели расширения | `@capability:<task>` появляется в общей очереди из `SEARCH_EXHAUSTED`; выбор и цель фиксирует `Kernel.step()` |
| Примитивы не являются генами | `extensions.learn`: тела и Python AST из внешних уравнений; геном v3 наследует идентификаторы тел, программы используют `apply` |
| Нет работы со спецификациями | `study` записывает источник и текст; компилятор понимает ограниченные словные уравнения, отдельно сообщает о неподдержанных циклах и блоках |
| Нет полного допуска расширения | freeze → отдельная свежая оценка → Linux seccomp/лимиты → регрессия → удаление примитива → admission → повторное выполнение при replay и исключение при rollback |

Здесь **не реализован универсальный читатель алгоритмической прозы**.
Словные функции могут быть скомпилированы без способности собрать полное
хеширование. Результат такого запуска должен оставаться `WITHHOLD`.

## Происхождение

Три файла `specification-*.json` содержат неизменённые текстовые фрагменты
разделов 4.1.2, 4.2.2, 5.1.1, 5.2.1, 5.3.3 и 6.2 официального
[NIST FIPS 180-4](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.180-4.pdf).
Текст извлечён `pdftotext -layout`, SHA256 исходного PDF:
`0455b406d89648d20cbde375561e19c245b9815e894164c2670772e3d54deb82`.
Выбор источника и ширины слова делает сопровождающий; разбор формул,
построение IR/source и выбор кандидата выполняет ядро. В runtime отсутствуют
реализация SHA-256, её шаблон или вызов библиотечного хеша как операция языка.
Хеши для идентификаторов/журнала не доступны сгенерированным программам.

`mechanism-fixture.json` — открытый контроль сопровождающего: прежний навык
strip и две задачи XOR с разными именами входных полей. После неудачи старого
поиска Nova выбирает цель, компилирует уравнение, подбирает аргументы и фиксирует
кандидата. Затем внешний проверяющий генерирует 24 новых случая: 4 границы
диапазона и 20 случайных пар. Случайные значения создаются после freeze.
Этот контроль доказывает ограниченный перенос возможности, не открытие закона
XOR без внешних знаний и не прохождение SHA-256.

## Запуск и критерии

Код, протокол, спецификации и runner должны быть сохранены до испытания:

```bash
python scripts/run_capability_cycle.py \
  --state state/capability-cycle-v3.sqlite \
  --output experience/capability-cycle-v3/result \
  --protocol-commit PRE_REGISTERED_COMMIT
```

Runner отказывается от повторного использования состояния/каталога и проверяет
точный runtime и входы относительно указанного commit. Он сохраняет отдельные
журналы контроля и G12, freeze, проверки, cold replay и откат контроля.
Код возврата 2 означает, что строгий SHA-256 рубеж не пройден, даже когда
проверка механизмов завершилась PASS. Вывод `IDLE` не считается новой целью.

Читатель нового runtime понимает исходную историю 0.1 и точное обновление 0.2;
перед развитием G12 добавляется явное событие обновления в 0.3. Само обновление
движка не увеличивает поколение генома.

## Пределы доказательства

Свежие случаи скрыты от генератора до freeze через отдельный вызов API и
последовательность событий. Oracle является доверенным внешним проверяющим;
ядро не доказывает подлинность указанного человеком источника или ответов.
Опубликованные после опыта случаи остаются в журнале для replay и больше не
являются секретными. Прошедший контроль нельзя называть независимым внешним
бенчмарком.

Удаление тела примитива и сравнение с активными генами показывают причинную
зависимость результата в данном исполнении. Записанный провал прежнего поиска
доказывает ограничение **этого ограниченного поиска**, не невозможность выразить
функцию любым другим способом. Linux-изоляция дополнительно проверяет реальный
запрет открытия файлов и создания сокетов; без неё допуск закрыт.

## Фактический результат запуска

Код и протокол опубликованы до исполнения в commit
`473ed1d4f2086be406e79fb7d3f2a5722aab17d6`.

- Контроль: **PASS**, 24/24 свежих случаев; ablation без нового примитива —
  0/24. Прежний навык сохранён; следующая задача выбрана из существующей
  очереди и использует именно новый примитив с другими входными полями.
  Отдельный restart/replay и rollback контроля прошли.
- Продолжение G12: собственный выбор SHA-256 и собственный диагноз достигнуты.
  До знания о спецификации ядро выдало `KNOWLEDGE_MISSING`. После `study`
  сгенерированы и реально исполнены в sandbox шесть частичных функций
  `Ch`, `Maj`, две большие и две малые sigma. Полного кандидата нет.
- Строгий рубеж SHA-256: **WITHHOLD / SPECIFICATION_LANGUAGE_INCOMPLETE**.
  Fresh SHA holdout не раскрывался и не оценивался; admission отсутствует.
  Следующее требование, записанное ядром: компиляция обработки байтов/блоков
  и индексированных рекуррентных вычислений. Исполнимой следующей цели нет;
  последующий шаг вернул `IDLE`.
- Основной геном остался G12 без изменений; 11 прежних навыков, **66/66**
  проверок. Обновлённый runtime, знания и попытки сохранены в том же журнале.
  Полный cold replay прошёл, исходные 20 событий сохранены побайтно по
  каноническому JSON.
- **63 теста PASS**. Облачный [CI исходного кода](https://github.com/v37025337-pixel/nova-/actions/runs/35518758367)
  прошёл на Python 3.11/3.12/3.13, включая восстановление старых G8 и G12.

Пять механизмов теперь существуют для ограниченного класса словных уравнений.
**Полностью закрыть исходную задачу, включая самостоятельное построение
SHA-256, этот запуск не смог.** Ограничение обучения по алгоритмической
спецификации остаётся конкретной незавершённой частью; шесть функций или
успех XOR не заменяют её.

```bash
  --state state/capability-restored.sqlite
python -m nova_core --state state/capability-restored.sqlite status
```
