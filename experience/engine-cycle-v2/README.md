# NOVA: обновление поисковой стратегии и продолжение до поколения 12

**Фактический результат — PASS, поколение 8 → 12.** Сохранены все восемь
исходных навыков, принята одна новая политика движка и три новые программы.
В активном геноме теперь 11 программ и один ген поисковой политики.

Код runtime, протокол и новые данные опубликованы перед запуском в commit
[`872d8cda`](https://github.com/v37025337-pixel/nova-/commit/872d8cdaf493f25ac55a604a6cc53ba24a8a26aa).
После публикации runtime и входы не менялись. До фиксации использовались unit
fixtures и старые обучающие задачи для разработки; новые holdout-результаты
не использовались для подстройки. Новые примеры и эталоны синтетические,
подготовлены разработчиком. Это проверка конкретных возможностей поиска.

## Что выполнило ядро

| Поколение | Изменение | Проверка | Исполнения поиска |
|---|---|---|---:|
| 9 | Новый порядок операций, отсечение типов, ранняя остановка, унарный поиск, глубина 4 и приоритет по прошлой стоимости | 9/9 свежих holdout; 48/48 примеров прежних навыков | 599 вместо 1 626 на старом train |
| 10 | JSON → очистка текста → верхний регистр → JSON | 3/3 holdout | 230 |
| 11 | Запись имени и длины с использованием программы поколения 10 | 3/3 holdout | 63 |
| 12 | Сериализация записи с использованием программы поколения 11 | 3/3 holdout | 25 |

Нативная политика получена из частот операций в восьми прежних программах.
На прежних обучающих задачах она сократила число исполнений на **63,16%**;
для измерения использовалась память до исходного приёма каждой задачи.
Готовый ответ самой задачи не давался ей через recall.

До изменения политики старый поиск не решил обучающую часть первой новой
задачи за 12 000 попыток. После приёма политики она решена за 230, а её
независимый holdout пройден полностью. На дополнительных новых запросах:
**12/12**. На прежних внешних запросах к унаследованным навыкам: **25/25**.
У двух следующих программ подтверждено использование непосредственно
предыдущего гена; результаты удаления зависимости сохранены в `steps.json`.

Контроль SHA-256 снова получил `WITHHOLD / SEARCH_EXHAUSTED` после 6 274
исполнений. Кандидата нет, holdout не потреблён. Язык не получил нового
примитива хеширования. После этой попытки очередь вернула `IDLE`; фонового
процесса обучения не осталось.

## Авторство и граница результата

Разработчик добавил механизм совместимого перехода между версиями runtime,
пространство допустимых мутаций и проверочные задачи. NOVA сама построила
конкретную политику и три программы в этом пространстве. Политика меняет
реальное исполнение поиска и выбор задач, хранится в общем геноме и проходит
общие admission/replay/rollback. Произвольное переписывание исходников,
изобретение новых примитивов, сознание и общий интеллект этим не доказаны.

CODE, LOGIC, THINKING и INTELLIGENCE оставили проверяемые записи в одном
workspace каждого шага. Использованы один runtime, одна очередь, одна
причинная память и один журнал. Решения проверочного набора движка не были
добавлены в память последующего обучения.

## Сохранность и воспроизведение

Исходные 12 событий поколения 8 сохранены без изменений. Итоговый журнал
содержит 20 событий, включая явный переход host runtime и нативную мутацию.

Итоговый head:

`7dc199de2af009abe40956ee91438adc425b61c3f014a5d7cf07894375d9e75b`

Полный replay резервной копии в отдельном процессе прошёл успешно. На другой
копии выполнен откат к поколению 8: прежняя стратегия восстановлена, все 25
унаследованных запросов снова верны. Основное состояние осталось на поколении
12. Записанная часть цикла после первоначального восстановления заняла около
124,6 с, холодная проверка — 34,7 с в этой среде. Сокращение числа поисковых
исполнений не означает такого же сокращения времени полного replay.

Восстановить сохранённое поколение 12 в **новый** файл, Python 3.12:

```bash
python scripts/run_development_chain.py --restore experience/engine-cycle-v2/journal.json --state state/evolved.sqlite
python -m nova_core --state state/evolved.sqlite predict 120-deep-serialized --input '{"payload":"\"  новый шаг  \""}'
python -m nova_core --state state/evolved.sqlite verify --expected-head 7dc199de2af009abe40956ee91438adc425b61c3f014a5d7cf07894375d9e75b
```

Выход программы — JSON-строка с `name: "НОВЫЙ ШАГ"` и `length: 9`.
Для следующего обучения используйте тот же `state/evolved.sqlite` и новые
задачи. Повторный `upgrade` уже не требуется.

Повторить именно этот опыт с другим файлом состояния и каталогом:

```bash
python scripts/run_engine_cycle.py --protocol-commit 872d8cdaf493f25ac55a604a6cc53ba24a8a26aa --state state/engine-repeat.sqlite --output experience/engine-cycle-v2-repeat
```

Повтор на тех же данных проверяет воспроизводимость и не является свежим
обучающим испытанием. Скрипт отказывается перезаписывать существующее состояние.

## Доказательства

- `protocol.json`, `trial.json`, `corpus.json`, `queries.json` — зафиксированные входы.
- `upgrade.json` — поддержанный разработчиком переход runtime без изменения памяти.
- `steps.json`, `engine-policy.json`, `genes/` — нативные решения и полные gate.
- `parent-search-probe.json` — исчерпание старого поиска на новом train.
- `query-results.json` — 12 новых и 25 прежних запросов.
- `journal.json`, `genome.json`, `causal-memory.json` — полное сохранённое состояние.
- `audit.json`, `restart-stdout.json`, `rollback-receipt.json` — replay, restart и откат.
- `run-summary.json` — все десять критериев PASS и фактические времена.
- `unit-tests.txt`, `verification.json` — 46 тестов, manifest и сборка/запуск wheel вне репозитория.

GitHub Actions проверяет код на Python 3.11–3.13, а на Python 3.12 дополнительно
восстанавливает и воспроизводит сохранённые поколения 8 и 12.
