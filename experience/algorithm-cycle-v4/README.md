# Продолжение G12: алгоритмические спецификации

Этот каталог фиксирует отдельный эксперимент runtime 0.4. Его исходная точка —
неизменённый журнал основного G12 из `capability-cycle-v3/result/journal.json`,
head `87a2fb19b56830c65d5b0296e41d97acfdb5f9a0579c3df23026de4627590fa3`.
До запуска в Git фиксируются runtime, протокол, проверяющий сценарий, новые
документы и следующая задача. Свежие проверочные входы создаются позднее.

## Откуда берётся реализация

Разработчик добавил ограниченный читатель рекуррентной нотации и компилятор
байтов, массивов и циклов. Он не добавлял готовую реализацию SHA-256 в runtime.
Три раздела NIST FIPS 180-4 уже находятся в памяти G12. Дополнительно подаются
неизменённый текст раздела 3.1 о нотации и явно указанная оператором конвенция
интерфейса UTF-8/hex. Константы, формулы, границы и порядок действий извлекает
компилятор из документов; именование алгоритма не выбирает готовый шаблон.

Источник: [NIST FIPS 180-4](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.180-4.pdf).
SHA-256 файла PDF: `0455b406d89648d20cbde375561e19c245b9815e894164c2670772e3d54deb82`.
Это обучение исполнению внешней спецификации, **не изобретение SHA-256** и
не общий читатель естественного языка. Поддержанный вход — UTF-8 до 1024 байт.
Независимый тест на другом 16-битном алгоритме проверяет, что тело меняется
вслед за константами, формулой и числом раундов в документе.

## Обязательная последовательность

1. Полный replay G12 и явный переход runtime с сохранением старых событий.
2. Регистрация следующей задачи `130-hash-record` и фиксация её
   `SEARCH_EXHAUSTED` до появления нового примитива.
3. Чтение двух дополнительных документов; собственный выбор ядром старого
   дефицита SHA-256, диагностика и фиксация тела примитива/адаптера.
4. Только после freeze — 24 новых случайных примера от внешнего проверяющего,
   включая границы блоков, padding, Unicode, NUL и 1024 байта.
5. Изолированная оценка, прежний holdout, регрессия всех навыков, ablation,
   затем admission G13. `hashlib` находится только у внешнего проверяющего.
6. Полное воспроизведение G13 новым процессом. Ещё один новый процесс делает
   обычный `step`, без подсказки идентификатора следующей цели.
7. Для G14 требуется использование принятого адаптера G13 в следующей программе,
   её holdout, повторная регрессия, новые запросы и cold replay.
8. На отдельной копии проверяется rollback к исходному геному G12.

Фиксированные контрольные векторы в unit-тестах — открытая проверка компилятора,
они не называются fresh-blind. Следующая задача подготовлена оператором;
её выбор и решение должны принадлежать ядру. Runtime в ходе прогона не меняется.

## Запуск

```bash
python scripts/run_algorithm_cycle.py \
  --state state/algorithm-cycle-v4.sqlite \
  --output experience/algorithm-cycle-v4/result \
  --protocol-commit COMMIT_WITH_THIS_PROTOCOL
```

Сценарий требует новых путей состояния и результата. Он проверяет совпадение
исходников и входов с предварительным commit. `result/run-summary.json`
получает PASS только при прохождении всех обязательных проверок.

## Фактический результат: PASS, G12 → G13 → G14

Предварительный commit исходников и протокола:
[`63226976d944ff9b95e0e0463f381b0229c4dda9`](https://github.com/v37025337-pixel/nova-/commit/63226976d944ff9b95e0e0463f381b0229c4dda9).
Прогон завершился за 423,37 секунды без изменения runtime и повторного подбора
кода по свежим ответам. Все 14 условий сводного отчёта выполнены.
