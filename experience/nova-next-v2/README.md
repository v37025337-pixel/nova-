# Captured HTTPS experiment: Nova Next

The runtime chose its goals from source-derived graphs. It received source URLs,
without a selected query or supplied target program. Candidate source was frozen
before each fresh pair of repository downloads. Captured texts and receipts are
in `journal.json.gz`; detailed actions are losslessly archived in `actions.json.gz`.

Two mechanisms were admitted: maximum downstream impact and total reachable
pairs. Each passed 24/24 induced graph views from two fresh repositories. An
intermediate perfect candidate was withheld because a baseline also passed
24/24. A third candidate reuses the acquired reachability mechanism but awaits
new sources: the eight configured repositories have been consumed.

These are two generations in a new lineage inheriting 21 Nova G22 skills. They
are not an admission into the unchanged historical Nova G23 protocol.

The regression of inherited skills passed 192/192. The independent verifier
recomputes the journal without network access, tests restored compiled programs
and exercises rollback on the recorded checkpoint before the next proposal.

Run from the repository root on Python 3.12 / Linux x86-64:

```bash
python scripts/verify_nova_next.py
```

The final pending candidate is not included in the acquired skills. See
`result.json` for exact attempts, baseline comparisons, failures and limitations,
and `verification.json` for replay evidence. Programs are readable under
`programs/`; they require the graph and inherited-function calling convention
implemented by `nova_next.worker`.

Captured upstream source remains under its original license. Corresponding
license texts and repository links are included in `upstream-licenses/`.
