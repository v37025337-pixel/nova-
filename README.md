# NOVA 0.4 — единое ядро с наследуемыми расширениями языка

NOVA — запускаемое экспериментальное ядро с постоянной памятью и нативным
построением программ по примерам. Один рабочий цикл связывает постановку задачи,
обнаружение дефицита, поиск решения, исполнение, независимую от поиска проверку,
приём нового поколения и последующее использование его программ. CODE, LOGIC,
THINKING и INTELLIGENCE работают внутри одного `Kernel` с одним состоянием,
одной очередью и одним причинным журналом с первого исполняемого commit.

Это новая реализация. Архитектурные уроки YADO перенесены в контракты и проверки;
старые модули и их исторические статусы автоматически не наследуются.

## Быстрый запуск

Нужен Python 3.11–3.13. Для запуска из репозитория дополнительных пакетов нет.

```bash
python -m nova_core --state state/nova.sqlite learn examples/three_generations.json --steps 3
python -m nova_core --state state/nova.sqlite status
python -m nova_core --state state/nova.sqlite predict 30-record --input '{"text":"  новый разум  "}'
python -m nova_core --state state/nova.sqlite verify
```

Последняя задача возвращает `{"name":"НОВЫЙ РАЗУМ","length":11}`.
Все команды завершаются. Для следующего ограниченного запуска:

```bash
python -m nova_core --state state/nova.sqlite develop --steps 10
```

Пример `three_generations.json` — открытый учебный набор, подготовленный
разработчиком. Код трёх решений выбирает ядро. Это воспроизводимая проверка
связности обучения и наследования, а не независимый тест общего интеллекта.

## Алгоритмические спецификации в 0.4

Добавлен ограниченный язык байтов, массивов и циклов `nova.sequence.v1`.
Ядро читает типографские уравнения и рекуррентные алгоритмы: извлекает из
документа константы, начальное состояние, границы циклов, порядок присваиваний
и выходных слов, затем строит IR и исполняемый Python AST. Тело алгоритма
хранится в общем геноме вместе с происхождением знаний.

Читатель спецификаций и элементарные операции написаны разработчиком.
В runtime нет готового SHA-256, таблицы его констант или выбора реализации по
названию алгоритма. Это компиляция внешнего математического описания в пределах
поддержанной нотации; самостоятельное изобретение алгоритма не заявляется.
Тот же читатель проверяется на другом 16-битном алгоритме с иным порядком байтов,
состоянием и числом раундов. Вход последовательностного примитива — текст UTF-8
до 1024 байт; массивы и число итераций ограничены.

Протокол продолжения G12, свежая проверка SHA-256 и следующая задача:
[algorithm-cycle-v4](experience/algorithm-cycle-v4/README.md).
Правила приёма, seccomp, единый журнал и откат сохраняются.

Фактический прогон 0.4: **G12 → G13 → G14, PASS**. Nova выбрала сохранённый
дефицит SHA-256 и скомпилировала полный алгоритм из спецификации. На свежем
holdout получено 24/24, после удаления примитива — 0/24; 11 прежних навыков
сохранили 66/66. После cold replay ядро само выбрало следующую задачу и за
8 кандидатов составило программу из нового SHA-навыка и прежней обработки
имени. Итог: 78/78 по 13 навыкам, 8/8 новых запросов, полный replay G14 и
rollback копии к G12. [Сводка проверок](experience/algorithm-cycle-v4/result/run-summary.json).

## Развитие языка в 0.3

В той же очереди появились цели `@capability:<task>`: ядро само выбирает
сохранённый `SEARCH_EXHAUSTED`, различает достижение бюджета и исчерпание
ограниченного поиска, записывает гипотезу о дефиците представления и потребность
в знаниях. Исчерпание поиска **не считается доказательством невозможности**.

Математические спецификации подаются через `study`. Тела новых примитивов
генерирует компилятор ядра; их IR, точный source, происхождение и идентификаторы
входят в геном. Поддерживаются чистые уравнения над беззнаковыми словами шириной
1–32 бита: битовые операции, сложение, вычитание, умножение, ограниченные сдвиги
и вращения. Формулы могут иметь 1–3 аргумента. Произвольный Python не принимается.

```bash
python -m nova_core --state state/nova.sqlite study specification.json --steps 1
python -m nova_core --state state/nova.sqlite assess fresh-evaluation.json
```

`study` получает `{id, source, title, width, text, provenance}`; пример `text`:
`mix(x,y) = x ^ y`. Это описание математического закона от оператора, не
самостоятельное открытие закона ядром. `assess` получает
`{"freeze":"<идентификатор зафиксированного кандидата>","rows":[...]}`.
Нужно 2–32 новых примера того же формата, что `holdout`; ответы даёт независимый
проверяющий. Генератор кода не получает эти примеры до фиксации кандидата.

Приём требует compile/исполнения в отдельном процессе, 100% на train, прежнем
holdout и новом holdout, сохранения всех активных навыков и ухудшения после
удаления примитива. Ошибка проверки расходует набор; ошибка инфраструктуры
оставляет кандидата ожидающим. Повторное использование входов и изменение
генома между freeze и оценкой отклоняются. Replay заново выполняет проверки;
rollback исключает новые тела из активного языка.

Изоляция расширений требует Linux x86_64/aarch64 с seccomp. Дочерний процесс
ограничен по времени и памяти, не получает журнал или знания и не может
открывать файлы, создавать сокеты, запускать процессы. На неподдерживаемой
платформе расширение не принимается. Обычный старый поиск по выражениям
по-прежнему работает без такого процесса.

Проверенный запуск 0.3: контроль расширения прошёл 24/24 свежих случаев,
регрессию, ablation, restart и rollback; следующий навык использовал новый
примитив. В основном G12 ядро само выбрало SHA-256 и скомпилировало шесть
вспомогательных функций из NIST, но полный алгоритм не собрало:
`WITHHOLD / SPECIFICATION_LANGUAGE_INCOMPLETE`. Сохранены 11 навыков, 66/66
прежних примеров. G13 не объявлен.
[Протокол и фактические результаты](experience/capability-cycle-v3/README.md).

## Развитие движка и следующий шаг

Сохранённый прогон продолжил поколение **8 → 12**: одна принятая политика
движка и три новые программы. Поиск на прежних обучающих задачах потребовал
599 исполнений вместо 1 626; на новых запросах получено 12/12, на повторных
запросах к унаследованным навыкам — 25/25. [Результаты и восстановление](experience/engine-cycle-v2/README.md).

Поисковая политика теперь является наследуемой частью общего генома. Ядро
считает частоты операций в собственных принятых программах и строит ограниченную
мутацию: порядок операций, проверка типов до исполнения, ранняя остановка,
приоритет унарного поиска, глубина до 4 и учёт стоимости прошлых неудач в очереди.
Бюджет остаётся 12 000 исполненных кандидатов на задачу.

```bash
python -m nova_core --state state/learned.sqlite evolve experience/engine-cycle-v2/trial.json --steps 1
python -m nova_core --state state/learned.sqlite learn experience/engine-cycle-v2/corpus.json --steps 4
python -m nova_core --state state/learned.sqlite verify
```

`evolve` помещает проверку движка в общую очередь. Тот же `step` строит кандидата,
измеряет его, принимает новый геном или записывает `WITHHOLD`. Приём требует
снижения суммарного числа поисковых исполнений на старых обучающих задачах,
успеха на отдельном проверочном наборе и сохранения всех прежних навыков.
Решения проверочных задач не добавляются в память для последующего обучения.

Правила мутации и переход между исходниками runtime написаны разработчиком.
Конкретную политику и последующие программы строит NOVA. Это ограниченное
развитие стратегии движка; новые примитивы и произвольные изменения Python-файлов
ядро не изобретает. [Протокол и устройство](docs/engine-evolution.md).

## Что действительно работает

Первоначальная проверка расширения грамматики на runtime 0.2 завершилась
**WITHHOLD на выборе цели**. Nova оставила SHA-256 в ожидании новой памяти и
вернула `IDLE`. Это историческая точка остановки перед изменениями 0.3 и 0.4.
[Протокол первоначальной проверки](experience/grammar-challenge-v1/README.md).

- **Память:** SQLite, транзакционный журнал, последовательные хеши, восстановление
  состояния из событий, проверка исходников исполняемого движка.
- **Общая причинная память:** событие постановки задачи → предыдущая попытка →
  события освоения использованных генов → новый код → измеренный результат.
- **Очередь задач:** PENDING / RETRY_READY / WAITING_FOR_NEW_MEMORY / ADMITTED /
  EVALUATION_CONSUMED; очередь восстанавливается из того же журнала.
- **Логика:** точная JSON-семантика, проверка контрактов и результатов.
- **Выбор цели:** сначала наибольшая наблюдаемая ошибка на обучающих примерах;
  исходно при равенстве — порядок идентификаторов. Принятая политика учитывает
  стоимость прошлой попытки и даёт новым задачам пройти до дорогого повтора.
- **Построение программы:** ограниченный поиск выражений по обучающим примерам,
  композиция ранее принятых программ, генерация Python AST и выполнение кода.
- **Проверка:** отдельные holdout-примеры, улучшение относительно явно указанного
  baseline, регрессия всех активных задач, удаление зависимостей для ablation.
- **Поколения:** новый принятый набор программ наследует активный родительский
  набор. После нового опыта исчерпанный поиск может получить новый контекст.
- **Genetics:** ген — выражение и его точный Python-source; геном — набор генов,
  привязки задач и хеш родительского генома. Новые гены строятся нативно и могут
  вызывать унаследованные гены. Предложенная мутация становится активной только
  вместе с успешным admission в одной транзакции.
- **Откат:** возврат к предку с сохранением исходных событий и неудачных попыток.

Один SQLite-журнал — единственный источник рабочего состояния. Отдельные mutable
manifest, active pointer и кэш опыта не конкурируют за право определять текущую
версию. Кэш проверенного префикса живёт только в процессе; он сверяется с хешами
журнала на каждом чтении. `verify` всегда пересчитывает всю историю.
Статический манифест релиза приведён в `canonical/release.json`.

| Функция единого runtime | Реальная работа |
|---|---|
| CODE | Поиск выражения, композиция генов, Python AST, исполнение |
| LOGIC | Контракты, измерение дефицита, проверка истины результатов и мутации |
| THINKING | Выбор следующей цели из очереди и причинная связь с прежними попытками |
| INTELLIGENCE | Подбор исполнимых генов по входам задачи и опыту, выбор стратегии их использования |

Каждый шаг хранит общий `workspace.context`, результаты всех четырёх функций
и причинные ссылки. Файлы разделяют ответственность кода; собственного runtime,
базы, очереди или автономного состояния у этих функций нет.

## Свои задачи

Передайте JSON-массив задач в `learn path/to/tasks.json --steps 10`. Формат задачи:

```json
{
  "id": "sum-v1",
  "source": "operator:my-labelled-examples",
  "train": [
    {"input":{"x":2,"y":7},"output":9},
    {"input":{"x":5,"y":-3},"output":2}
  ],
  "holdout": [
    {"input":{"x":31,"y":17},"output":48},
    {"input":{"x":-8,"y":-9},"output":-17}
  ]
}
```

В каждом разделе требуется 2–32 примера. Входы разделов не пересекаются.
`source` — обязательная метка происхождения, указанная оператором; ядро не считает
её доказательством того, что данные получены с указанного сайта.

Поисковик получает только `train`. Первый точный обучающий кандидат фиксируется,
после чего оценивается на `holdout`. Провал holdout сохраняется как `WITHHOLD`.
Тот же набор после такой проверки повторно не используется для приёма, в том
числе после отката или переименования задачи. Для следующего экспериментального
приёма нужны новая задача и действительно новые проверочные данные.

Если поиск исчерпан до появления кандидата, holdout ещё не потреблён. Повтор
возможен после изменения набора исполнимых программ или поисковой политики. Без нового контекста ядро
не повторяет ту же исчерпанную попытку. `IDLE` означает отсутствие доступной
новой попытки и не является признаком успешного решения всех задач.

Baseline — значение первого входного поля по алфавиту. Приём требует 100% на
train и holdout, большего числа правильных holdout-ответов, чем у baseline,
и отсутствия регрессий. Это конкретный локальный критерий, а не оценка интеллекта.

## Память, проверка и откат

```bash
python -m nova_core --state state/nova.sqlite backup state/backup.sqlite
python -m nova_core --state state/nova.sqlite export > journal.json
python -m nova_core --state state/nova.sqlite queue
python -m nova_core --state state/nova.sqlite memory
python -m nova_core --state state/nova.sqlite genome
python -m nova_core --state state/nova.sqlite rollback 1
python -m nova_core --state state/nova.sqlite verify --expected-head SAVED_HEAD_HASH
```

Для резервирования используется SQLite Backup API: копирование только основного
файла при работающем WAL не является корректной резервной копией.
`verify` заново выполняет выбор задачи, синтез и проверку каждой попытки из
зафиксированных данных; сеть не требуется. Хеш внешне сохранённого `head`
позволяет обнаружить усечение хвоста журнала. Без внешнего хеша удалённый
корректный хвост нельзя отличить от более раннего состояния. Хеши не являются
электронной подписью против владельца файловой системы.

Состояние закреплено за точными исходниками ядра и minor-версией Python.
Реализованы явные переходы из канонических runtime 0.1, 0.2 и 0.3 в текущий 0.4 при той же
minor-версии Python. Исторические переходы и события расширения языка 0.3
пересчитываются с прежней семантикой и точными старыми манифестами.
Неизвестные исходники отклоняются.
Откат генома возвращает прежнюю поисковую политику и навыки. Для возврата самого
host runtime к 0.1 используйте прежний commit с сохранённой контрольной точкой.

## Точная граница возможностей

Базовый поисковик строит программы из заданных операций: обработка текста,
числа, сравнения, JSON, списки, чтение полей и сборка объектов. Бюджет поиска —
12 000 проб выражений, глубина поиска операций — исходно 3, с принятой политикой до 4. Поддерживается до 24 уровней
вызовов ранее принятых программ. Конструктор выходного объекта имеет собственный
ограниченный рекурсивный бюджет. Неподдерживаемые задачи сохраняют `WITHHOLD`.

Self-development в этой версии — собственный выбор очередной задачи, построение
и проверка гена, изменение активного генома, возврат к прежним дефицитам после
нового опыта, а также проверяемая мутация поисковой политики в том же геноме.
Ядро выбирает программы и параметры стратегии, а также компилирует тела новых
словных и последовательностных примитивов из внешних математических спецификаций. Исполняющий код,
язык спецификаций, элементарная арифметика слов, правила мутации и критерии приёма
написаны разработчиком; происхождение знаний и примеров записывается отдельно. Произвольный host-source self-rewrite,
полный перенос исторической памяти YADO, самостоятельное изучение интернета,
фоновый сервис и сознание в этой версии не реализованы и не заявляются.
Поколения считают проверенные приёмы программ, поисковых политик и расширений языка. Это не шкала G0/G2/G3 YADO.

Происхождение архитектурных решений и конкретные исходники YADO указаны в
`docs/yado-lineage.json`. Обучение по произвольным алгоритмическим описаниям
остаётся за пределами поддержанной нотации. Результат каждого поколения
определяется сохранённым протоколом и журналом; открытые тесты компилятора
сами по себе не означают прохождения поколения 13.
