# Активное использование UCR в Nova 0.8

До 0.8 мост сохранял анализ кода и гипотезы UCR как наблюдения. Поиск программ
в `observations.propose()` вызывал только прежний синтезатор. Поэтому наличие
UCR в журнале не означало его участия в создании навыков.

Теперь после `GOAL_FROZEN` и `SEARCH_FROZEN` ядро вызывает
`nova_core.ucr_development.synthesize()`. Интерфейс принимает только обучающие
строки, память и текущую политику прежнего поиска. Диагностические и свежие
проверочные примеры в UCR не передаются.

1. Для каждой попытки создаётся новый UCR с реестром точных операций Nova.
   Регистрация включает 15 существующих операций и восемь прежних констант.
2. UCR ищет композиции последовательно до глубины 3, максимум 2048 деревьев
   и 12 возвращаемых кандидатов на раунд. Поддерживается одно входное поле.
3. Адаптер проверяет структуру дерева и переводит только разрешённые узлы
   в `nova.expression.v1`. Текст кандидатов не выполняется. Все восемь
   обучающих строк повторно проверяются точной семантикой Nova.
4. Если подходящего кандидата нет, используется прежний синтезатор, включая
   его наследуемые программы и политику. Причина и оба счётчика сохраняются.
5. Кандидат проверяется в изолированном процессе и фиксируется. Прежний gate
   допуска требует 16–24 свежих строк, прежний диагностический набор,
   регрессию всех навыков и проверки наследуемых зависимостей. Известные входы
   не могут стать свежими посредством переименования источника.

UCR ранжирует гипотезы по собственному разбиению обучающих данных. Поле
`internal_split` в журнале явно отражает, что это часть поиска. Статус
`TRAINING_FIT` не означает admission. Реестр грамматической эволюции UCR
не переносится в геном Nova автоматически.

## Совместимость и границы

Версия runtime — `nova.kernel.v8`. В манифест добавлены хеши внешнего UCR
и его пакета. Для v7 сохранён полный точный манифест; при воспроизведении
старого события вызывается старый поиск. Обновление состояния — отдельное
событие `runtime_upgrade` с регрессией всех активных программ.

Выбор цели по парам полей остаётся прежним, включая предел первых 64 пар.
UCR помогает искать программу для выбранной цели; он не доказывает
предсказуемость случайных связей и не меняет автоматически критерии допуска.
Адаптер ограничен композицией существующих операций. Его участие само по
себе не доказывает расширение возможностей по сравнению с прежним поиском.

## Проверка

```bash
python -m unittest discover -s tests -v
python scripts/verify_release.py
python scripts/run_ucr_development.py --output /tmp/nova-ucr-development
```

`tests/test_ucr_development.py` проверяет реальное получение программы от UCR,
перевод и выполнение на невидимых входах, отсутствие проверочных строк в
поиске, admission после фиксации, перезапуск, отрицательный контроль,
ограничение бюджета и сохранение прежнего поиска как запасного пути.
Учебный admission в тесте начинается с пустого состояния и не является G23.

Реальный прогон продолжает сохранённый журнал G22 без новых задач и без
выдуманных свежих ответов. Он сохраняет переход runtime, решение ядра,
контроль прежним синтезатором на той же обучающей выборке, регрессию и полный
журнал. Результаты: [отчёт опыта](../experience/ucr-development-v1/README-RU.md).
