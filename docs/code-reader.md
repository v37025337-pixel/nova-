# Universal Code Reader 16 в Nova

Вместо раннего reader подключён предоставленный пользователем файл
`universal_code_reader-17.py`, внутри которого указана версия `16.0`.
Его SHA-256 и хеши интегрированных файлов записаны в
`canonical/code-reader.json`. Рабочий файл
`nova_tools/universal_code_reader.py` сохраняет самостоятельный Python API.

Доступны AST Python, JSON/JSONL/XML, машинная графовая запись, структурные
отношения, изучение поверхностной грамматики, `passport()`, вывод семантических
гипотез по наблюдениям, анализ трасс состояний, поведенческий эмулятор и
ограниченные механизмы эволюции грамматики UCR. Разбор названия языка не
означает полного понимания его семантики. Бинарный разбор возвращает байты,
строки и статистические признаки, без заявления о выполнении инструкций.

Мост Nova передаёт синтаксис и, при наличии `--traces`, когнитивные гипотезы
в `Kernel.observe()`. Сам UCR и эта интеграция написаны разработчиком.
Его внутренний реестр примитивов не становится автоматически геномом Nova.
Исторический runtime Nova 0.7/G22 и его точные хеши сохранены.

В Nova 0.8 появился отдельный активный путь: ядро вызывает UCR для поиска
нативных программ по обучающим примерам выбранной цели. Порядок фиксации,
проверки и допуска описан в [активном использовании UCR](ucr-development.md).

## Использование

```bash
python -m nova_tools.code_reader_bridge nova_core/kernel.py --output analysis/kernel-ir.json
```

Результат содержит полный IR, исходный текст, `source_base64` с точными байтами
и метаданные границ анализа. `restore_bytes()` проверяет хеш сохранённых байтов.
Паспорт доступен через `ReadResult.passport()`. Через Python API можно вызвать
`learn_grammar(samples)` для корпуса; это изучение формы, а не значения.

Для записи результата в существующее состояние:

```bash
python -m nova_tools.code_reader_bridge nova_core/kernel.py --output analysis/kernel-ir.json --state state/nova.sqlite --source-url 'https://github.com/v37025337-pixel/nova-/blob/COMMIT/nova_core/kernel.py'
```

Замените `COMMIT` на commit читаемой копии. Адрес задаётся вызывающей стороной:
мост не делает сетевой запрос и не удостоверяет удалённое происхождение.
Наблюдение явно помечено `derived_syntax_not_source_execution`.

Для вывода гипотез из внешне полученных наблюдений:

```bash
python -m nova_tools.code_reader_bridge program.aic --traces observations.json --max-depth 2 --output analysis/program-ir.json
```

`observations.json` — массив объектов с `inputs`, `output` и необязательным
`code`. Например: `{"code":"r = F(a,b)","inputs":{"a":2,"b":3},"output":5}`.
Для обоснованной гипотезы нужен набор разнообразных наблюдений. Содержимое
`code` не выполняется. Связь наблюдений с анализируемым файлом утверждает
вызывающая сторона; мост сам не устанавливает её. Полные переданные строки,
их хеш, цикл рассуждения, дефициты и предложенные проверки остаются в полном IR.

Статус UCR `holdout-supported` означает поддержку внутри его собственного
разбиения примеров. Эта часть данных участвует в ранжировании кандидатов,
поэтому статус не является независимой свежей проверкой и не разрешает
admission Nova. Исторические примеры остаются историческими.

## Совместимость и исправления

В новой версии повторно воспроизведены и исправлены следующие проблемы:

- Отсутствие восстановления исходных байтов, включая BOM и UTF-16 BE.
- Повторные ID общих AST-объектов: ID теперь определяется вхождением в дерево.
- Двойное добавление канонического слоя при общем парсере или ошибке Python/JSON.
- Совпадение JSON-путей ключей с `/` и `~`, молчаливое принятие повторных ключей
  и нечисловых значений. Правила распространяются и на JSONL.
- Непереносимый JSON для суррогатов и бесконечных Python-литералов.
- Отказ извлечения семантики для одноаргументных `F(x)` и `[F,x]`.

Теперь недекларированные `.aic`-символы представлены отдельными неявными
узлами и списком `implicit_symbols`. `unresolved_links` содержит именно
ссылки на отсутствующие узлы; позднее объявление снимает отметку неявности.
Это намеренное изменение представления v16. Бинарный IR дополнен сводкой
`summary.binary`; прежние байтовые блоки сохранены.

Мост принимает до 262144 байт источника и столько же байт файла наблюдений,
до 128 наблюдений и глубину композиции 1–3. В журнал передаются до 96 узлов:
сначала до 24 гипотез, затем синтаксис. Все сокращения значений и узлов
отмечаются явно. Полный IR можно сохранить через `--output`. Выход не может
перезаписать вход, файл трасс или состояние.

## Исторический опыт интеграции 0.7

Для повторения этого опыта нужен checkout commit `bf975f7`, где runtime
ещё соответствует указанным ниже исходным хешам. Для текущего runtime
используйте `scripts/run_ucr_development.py`.

```bash
python -m unittest discover -s tests -v
python scripts/verify_release.py
python scripts/run_code_reader_cycle.py --source-commit 5c47fe7a0425f579cb4c75bc2fe76df2c8b565d5 --output /tmp/nova-ucr-run
```

Опыт восстанавливает сохранённую G22, сверяет 21 исходник с указанным commit,
читает их через UCR, повторно исполняет исторические примеры действующих
программ и передаёт наблюдения в Nova. Затем запускает до трёх обычных шагов
ядра и отдельно проверяет перезапуск. Протокол выбран разработчиком; цель
этих шагов выбирает Nova. Источники и исторический опыт не выдаются за новые
сетевые данные. Итоги текущего запуска сохраняются в
`experience/ucr-v16-integration/summary.json`.
