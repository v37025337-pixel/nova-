# Подключение UniversalCodeReader

Пользователь передал `universal_code_reader.py` и разрешил включить его в
репозиторий. Рабочая копия находится в `nova_tools/universal_code_reader.py`;
она по-прежнему может использоваться одним самостоятельным файлом. Мост
`nova_tools/code_reader_bridge.py` подключает её к журналу наблюдений Nova.
Это добавленный разработчиком инструмент, а не новая самостоятельно созданная
способность или поколение ядра. Исходные файлы `nova_core` после проверенного
опыта 0.7 не менялись, поэтому его точное воспроизведение сохранено.

## Что исправлено в присланной версии

- В исходном коротком Python-примере обнаружены повторяющиеся идентификаторы
  AST и ссылки на несуществующие узлы констант. Идентификаторы теперь основаны
  на пути конкретного вхождения узла, а родитель использует его точный ID.
- Вход `EF BB BF FF` вызывал `UnicodeDecodeError`; UTF-16 BE нельзя было
  восстановить по тексту и указанной кодировке. Теперь исходные байты отдельно
  сохранены в `source_base64`, а `restore_bytes()` проверяет их SHA-256.
- JSON-ключи с `/` и `~` больше не создают совпадающие пути; повторяющиеся ключи
  и нечисловые константы отмечаются как ошибка разбора с сохранением токенов.
- Бинарные `.wasm` и `.class` представлены байтовыми блоками, без заявления
  о разборе инструкций. Непарные суррогаты и бесконечные Python-литералы не
  ломают переносимый JSON-вывод.
- Уровень разбора, незамкнутые ссылки `.aic` и повторные ID явно отражены в
  metadata. Распознавание расширения не приравнивается к пониманию языка.

## Использование

```bash
python -m nova_tools.code_reader_bridge nova_core/kernel.py --output analysis/kernel-ir.json
```

Выход содержит полный IR, исходный текст и точные байты в base64. Мост читает
до 262144 байт исходного файла за вызов. Самостоятельный класс reader работает
с переданными байтами и не читает файлы или сеть автоматически.

Для записи синтаксических наблюдений в существующее состояние v7:

```bash
python -m nova_tools.code_reader_bridge nova_core/kernel.py --output analysis/kernel-ir.json --state state/nova.sqlite --source-url 'https://github.com/v37025337-pixel/nova-/blob/COMMIT/nova_core/kernel.py'
```

В URL нужно подставить commit читаемой копии. URL задаёт вызывающая сторона:
мост не получает этот адрес из сети и не подтверждает происхождение удалённого
файла. В журнале явно указано `derived_syntax_not_source_execution`, отдельно
сохранены хеш исходных байтов и хеш полного IR. В наблюдения попадают первые
96 узлов; числа узлов и признаки сокращения/экранирования значений отражены явно.
Полный IR остаётся в `--output`. Команда не запускает `Kernel.step()` и не
регистрирует операторскую учебную задачу; дальнейшее решение принимает обычный
цикл ядра по отдельной команде.

Python обрабатывается через AST, JSON через дерево, простой `.aic` через
объявления и связи. Для JavaScript, C/C++, Rust и большинства остальных
расширений используется общий лексер. Сохранение или разбор кода не означает
изучение его семантики, получение новых алгоритмов либо доказанное понимание
любого языка любым ИИ.

Проверки: `python -m unittest tests.test_code_reader -v` и
`python scripts/verify_release.py`. Последняя сверяет также отдельный манифест
трёх файлов инструмента `canonical/code-reader.json`.
