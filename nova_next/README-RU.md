# Nova Next 0.1

Новое ядро наследует 21 проверенный навык Nova G22 и использует присланный
`ucr_autonomous_kernel-7.py` как источник отдельных валидаторов и моделей.
Один новый конвейер отвечает за наблюдение, выбор дефицита, синтез программы,
fresh-blind, admission, наследование и воспроизведение журнала.

В сетевом опыте ядро самостоятельно выбрало и приобрело **два механизма анализа
графов**. Третий кандидат использует приобретённый механизм, но ещё не допущен.
Это ограниченный исследовательский преемник. Он не демонстрирует общий интеллект,
свободное изобретение любых целей или неограниченное изменение собственного runtime.

## Что изменилось после разбора исходного файла

| Замечание | Реализация в новом ядре |
| --- | --- |
| Ответы генерирует тот же blueprint, который затем «открывается» | `oracle.py` независимо задаёт поведение через битовую матрицу и алгоритм Warshall. Синтезатор получает только обучающие пары; fresh-ответы ему недоступны. |
| Готовые семейства алгоритмов | Типизированная грамматика общих операций над отношениями, ограниченной итерации и арифметики. Синтезируется дерево и исполняемый Python-код. Это всё ещё конечный поиск, до 2048 кандидатов. |
| Синтетика названа реальными данными | Само ядро загружает Python-файлы по HTTPS, сохраняет исходный текст, URL, время, размер и SHA-256. Внешний код разбирается статически. |
| Девять слоёв дублирования | Один класс `Kernel`, один формат предложения и один admission. |
| Глобальный кэш переживает восстановление | Новое состояние находится в журнале. Рабочий кэш принадлежит инстансу и проверяет префикс цепочки. Восстановление пересчитывает события с начала. |
| Скрытый blueprint | Исходный файл сохранён побайтно; его blueprint дополнительно опубликован как `seed_blueprint.json`. Автономные admission-слои оригинала не используются. |
| Непроверяемые заявления о развитии | Каждое принятие требует свежего переноса, улучшения относительно активных программ и сохранения прежних навыков. Отказы остаются в журнале. |

## Реальный опыт

Протокол `experience/nova-next-v2/protocol.json` зафиксирован до сетевого запуска.
Вход — восемь адресов исходников разных репозиториев, без выбранной задачи,
целевой программы или ответов. Оба первых источника используются для наблюдения;
каждая последующая пара загружается после фиксации кандидата.

| Этап | Выбранная цель | Fresh-blind | Лучший прежний ответ | Решение |
| --- | --- | --- | --- | --- |
| Next G1 | Максимум достижимых функций из одной функции | 24/24, HTTPX и Werkzeug | 2/24 | Принято |
| Проверка следующего кандидата | Число достижимых пар функций | 24/24, Starlette и aiohttp | 24/24 | Отказ: улучшение не установлено |
| Next G2 | Число достижимых пар функций | 24/24, Flask и Click | 7/24 | Принято |
| Следующий кандидат | Число достижимых пар без прямого ребра | Ещё не проводился | — | Зафиксирован; пул источников исчерпан |

24 случая — это 12 различных индуцированных подграфов из каждого из двух
репозиториев, а не 24 независимых источника. Рёбра подграфов взяты из исходного
статического анализа. Циклы и ветвления дополнительно проверяются явными
контрольными примерами в тестах. Статические вызовы не доказывают фактическую
причинность или поведение программы во время исполнения.

Первый механизм найден за 34 попытки, второй — за 31. Поиск третьего сначала
исчерпывал бюджет. После приобретения второго механизма ядро построило за
165 попыток `вызов_приобретённого_механизма - число_прямых_рёбер`.
Это кандидат на наследуемое расширение, пока без доказанного свежего переноса.

Регрессия старых навыков: **192/192, 21 навык** при каждой оценке. Прежний runtime
Nova сохранён. Новая ветка имеет собственные Next G0 → G1 → G2; эти номера
не являются переименованием старого состояния Nova в G23.

Отдельно сохранён неудачный первый сетевой опыт `experience/nova-next-v1`:
восемь локальных DNS-ошибок, ноль наблюдений и допусков. Исправление транспорта
учитывает настроенный HTTPS-прокси. Протокол, журнал отказов и архив тогдашнего
runtime сохранены; неудачный опыт не засчитывается как успешный.

## Запуск

Нужны Linux x86-64 и Python 3.11–3.13. Изоляция использует существующий
seccomp-механизм Nova и завершается ошибкой, если он недоступен.
Для точного воспроизведения сохранённого опыта нужен Python 3.12.

```bash
python -m pip install .
nova-next --state /tmp/next.sqlite init
nova-next --state /tmp/next.sqlite run --steps 24
nova-next --state /tmp/next.sqlite status
nova-next --state /tmp/next.sqlite export --output /tmp/next-journal.json.gz
nova-next --state /tmp/restored-next.sqlite restore /tmp/next-journal.json.gz
```

Запуск конечный и выполняется по команде. Ожидание в журнале не означает
фоновый процесс, который продолжает работать после выхода.

Для нового опыта можно задать 2–32 источника при инициализации:

```bash
nova-next --state /tmp/custom-next.sqlite init --feeds feeds.json
```

Формат `feeds.json` — список объектов `{"url":"https://…/source.py","module":"package.module"}`.
Никаких целевых функций и ответов в нём нет. Пул неизменен внутри одной истории:
после его исчерпания ядро честно возвращает `MORE_INDEPENDENT_SOURCE_FEEDS_REQUIRED`.
В этой версии добавление источников в уже начатую историю и миграция между
изменёнными runtime ещё не реализованы. Для нового пула создаётся новый опыт;
это не продолжение прежнего генома. Перед началом длительного опыта нужно
подготовить достаточный пул независимых репозиториев.

Восстановить именно поставленный результат с двумя навыками:

```bash
nova-next --state /tmp/proven-next.sqlite restore experience/nova-next-v2/journal.json.gz
python scripts/verify_nova_next.py
python -m unittest discover -s tests -v
```

Восстановление не обращается в сеть. Оно повторно выбирает цели, синтезирует
кандидатов, вычисляет oracle, запускает скомпилированные программы и проверяет
допуски, регрессию и digest истории. 150 тестов прошли в проверенной среде.

## API и границы возможностей

`Kernel.predict(law, graph)` выполняет допущенный графовый механизм.
`Kernel.inherited_predict(name, inputs)` предоставляет унаследованные навыки Nova.
`Kernel.observe_states(id, stream)` и `predict_state(id, action, before)` используют
унаследованный fitter UCR29; неоднозначный результат возвращается как `AMBIGUOUS`.
Прогноз такого fitter не считается новым admission. В отдельной проверке он
перенёс правило длины результата реального `bytes(n).hex()` на три новых входа.

Цели пока принадлежат **трём заранее заданным структурным спецификациям**.
Ядро выбирает конкретный дефицит по ошибкам на наблюдениях и строит программу
из общей грамматики. Сам словарь вопросов и независимую спецификацию написал
разработчик. Oracle — отдельная реализация, но не независимая организация или
внешний подписанный сервис. Его реализация проверена на ручных примерах.
Масштабируемость на больших проектах не установлена: один захват ограничен
256 функциями, поиск ограничен числом кандидатов.

Синтезированные программы исполняются отдельным процессом с лимитами CPU/памяти
и seccomp. Внешний Python-код не импортируется и не исполняется. Сеть доступна
наблюдающему слою, а не сгенерированным программам. Доступ ограничен публичными
HTTPS-источниками, размером ответа и временем. При использовании настроенного
прокси разрешение DNS и сетевые ограничения делегируются ему; локальная
проверка публичных IP применима к прямому соединению. Это не универсальный
защитный сетевой шлюз.

Журнал защищает целостность и позволяет семантическое воспроизведение.
Сохранённый HTTPS-ответ остаётся локальным свидетельством получения данных;
он не является независимой подписью владельца сайта. Источники, ограничения
и отказы открыты для проверки.
